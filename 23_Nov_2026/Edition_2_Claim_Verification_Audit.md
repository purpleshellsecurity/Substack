## Required or recommended wording changes

1. **Defender endpoint health rollout:** Replace the overview wording with “Microsoft announced a consolidated endpoint health dashboard, with public preview rolling out over the following weeks.” The separate preview status isn't stated in the original paragraph.
2. **Sentinel Unified Data Management:** Explicitly identify as **public preview**. This is documented in the dedicated [connector catalog](https://techcommunity.microsoft.com/blog/microsoftsentinelblog/microsoft-ignite-2026-new-sentinel-connectors-announcement/4565258).
3. **Sentinel normalization:** Keep the source discrepancy visible: [Defender overview](https://techcommunity.microsoft.com/blog/microsoftthreatprotectionblog/ignite-2026-whats-new-in-microsoft-defender--sentinel/4569975) says “now available in preview”; [Sentinel dedicated post](https://techcommunity.microsoft.com/blog/microsoftsentinelblog/ignite-2026-whats-new-in-microsoft-sentinel/4571174) says “coming to public preview in December 2026”. Avoid the first-person “I would treat it...” in the factual report; suggested replacement: “Because the two announcements give different preview timing, tenant availability should be confirmed before use.”
4. **Edge:** Cite [dedicated Edge for Business post](https://blogs.windows.com/msedgedev/2026/11/17/edge-for-business-ignite-2026-innovations/) rather than Book of News alone. Extension safety GA (Microsoft 365 licensing), extension leak control preview (M365 E3), and Edge Sentinel connector preview (Sentinel license).
5. **WESP:** If stating supported Windows versions, specify October 2026 Windows 11 25H2 (26200.9818) and 26H2 (26300.9818), and MVI/Artifact Signing requirement from [Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/wesp/wesp-requirements).
6. **M365 BSM Azure status:** The [M365 BSM post](https://techcommunity.microsoft.com/blog/microsoft_365blog/ignite%E2%80%9926-spotlight-announcing-microsoft-baseline-security-mode-2026-general-ava/4572694) calls Azure and Windows private preview; a separate Azure BSM announcement describes Azure as public preview. Existing sentence explicitly anchors the status to M365 post, which is sourced but potentially misleading as a global availability claim. Consider keeping Azure BSM status out of Edition 2 and researching it in Edition 3.
7. **Perception triage:** Keep the existing qualification of 80% coverage of an analyzed ~8M-strong alert population, not 80% correct or 80% resolved. Source footnote confirms.
8. **ISOC:** The expanded SIEM/retention pricing applies only to eligible opt-in customers, not all existing Sentinel installations. Existing text handles this adequately; do not remove qualification.
